## 비교 시나리오


| 구분          | 내용                                                                   |
| --------------- | ------------------------------------------------------------------------ |
| 대상          | LangGraph, Pydantic AI, Microsoft Agent Framework                      |
| 시나리오      | 이상 감지 → 원인 분석(고정 응답) → 설비 조치(가짜 도구) → 결과 기록 |
| 환경          | 클라우드(서버리스 + Postgres), 엣지(라즈베리파이 + 로컬 저장소)        |
| 테스트        | 장애 복구·재개, 사람 승인(HITL)                                       |
| 변경 시나리오 | 실행 환경 이동, 흐름에 단계 추가                                       |
| 제외          | 속도, 모델 정확도 (개발자 최적화로 수렴하므로)                         |

### 1. 공정 비교를 위한 통제 조건

* **업무 로직 공통화** : 이상 판단, 조치 규칙은 프레임워크와 무관한 공통 모듈 하나로 두고 세 프레임워크가 똑같이 호출
* **동일 저장소** : 클라우드에서는 같은 Postgres 인스턴스를 스키마만 나눠 사용
* **실행 로그 공통 항목** : 실행 ID, 인스턴스 ID, 단계명, 시각, 조치 호출 카운트
* **반복 횟수** : 강제 종료 시점이 미세하게 달라질 수 있으므로 각 테스트 3회 반복, 결과가 엇갈리면 그 자체를 기록
* **기준 버전 고정** : 테스트 시작 시점의 각 프레임워크 버전을 기록

### 2. 지표 체계

#### A. 보장 지표: 이 동작이 되는가


| ID | 지표               | 판정 질문                                                       |
| ---- | -------------------- | ----------------------------------------------------------------- |
| R1 | 중간 재개          | 2단계 도중 종료 후 재호출 시 완료된 단계를 다시 실행하지 않는가 |
| R2 | 조치 멱등성        | 조치 직후·저장 전 종료 시, 재개 후 조치 호출이 1건인가         |
| R3 | 동시 재호출 안전성 | 같은 실행 ID 동시 재호출 시 중복·상태 섞임이 없는가            |
| H1 | 대기 중 종료       | 승인 대기 시 프로세스가 살아 있지 않아도 되는가                 |
| H2 | 새 인스턴스 복원   | 다른 인스턴스에서 승인 받아 정상 진행되는가                     |
| H3 | 거절 경로          | 거절 시 조치 없이 종료되는가                                    |
| H4 | 중복 승인          | 같은 승인 2회 전송 시 조치가 1회인가                            |

#### B. 변경 비용: 요구가 바뀔 때 얼마나 고치는가

변경 시나리오별 기록 항목


| 지표                 | 측정 방법                                               |
| ---------------------- | --------------------------------------------------------- |
| 변경 줄 수 / 파일 수 | 버전 관리 도구의 변경 통계 기준, 주석·빈 줄 제외       |
| 최고 변경 수준       | 이번 변경에서 나온 가장 높은 L 단계                     |
| 업무 로직 변경 여부  | 공통 모듈을 건드렸는가 (건드렸다면 그 자체로 감점 사유) |
| 보장 유지 여부       | 변경 후 A 지표를 다시 돌렸을 때 결과가 같은가           |

- 변경 수준 정의


| 수준 | 정의                                                  | 의미      |
| ------ | ------------------------------------------------------- | ----------- |
| L0   | 설정값만 변경                                         | 이상적    |
| L1   | 어댑터·연결 코드 변경 (저장소, 모델 클라이언트 등)   | 정상      |
| L2   | 워크플로우 정의 변경                                  | 허용 범위 |
| L3   | 프레임워크 내부 우회 (상속 덮어쓰기, 비공개 API 사용) | 위험 신호 |
